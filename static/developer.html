The four doors

The whole story, one press

The whole product in one press, about twenty seconds end to end: profile, booking, risk warnings, sharing, two disruptions, spending tiers, the kill switch, and the audit trail — every feature in sequence, running through the same code real users hit, so what you see here is what ships. Each press builds a fresh trip, so it is safe to run in front of anyone, twice.

The presenter's guide

The six-minute live demo, planned like a runbook: seven timed acts, every line to type and every line to say written down, and a recovery table for the things that can go sideways mid-presentation — each mapped to what to do and what to tell the room. Nobody has to improvise on stage.

The manual builder

The agent page with the conversation removed and the plumbing made visible: explicit search forms, result tables, the cost ledger, the alert schedule, and the per-lane handoff, all on one page along a progress rail. Runs without the language model, which makes it the right place to reproduce an issue precisely.

use it to: drive every step by hand and see the machinery Open /book

How to test it

The acceptance checklist: six scenarios covering the promises the product makes — booking by sentence, small delay vs real breakage, meetings as commitments, whole-trip cancellation priced first, the agent acting only inside its spending cap, and role-based sharing where a host sees every time and not one price. Each case states the expected result and the known looks-wrong-but-isn't cases, so testers file real bugs instead of design decisions.

The four doors

The worked example

A frozen scenario rendered from GET /api/state: one delayed long-haul, the knock-on graph, and ranked recovery plans. Deterministic — the pytest suite asserts the S$423 headline, and python cli.py --base written prints the same figures straight from the engine, no server involved. If a number here ever disagrees with the tests, that is a bug, not a rounding story.

use it to: verify the arithmetic is computed, not typed Open /demo

The whole story, one press

One press fires POST /api/story, which builds a fresh owner and trip and drives eleven chapters through the same handlers the UI calls — profile, booking, risk flags, share, delay, cancel, permission tiers, kill switch, audit trail. Nothing is seeded: the page only renders the response, and every run creates new rows, so it is safe to press twice.

use it to: exercise the whole API surface in ~20s Open /story

The presenter's guide

The /story arc performed by hand on the live app: seven timed acts, each line to type in a blue box and each line to say in italics, plus a failure table mapping what went wrong (replay route miss, degraded port, cap refused the auto-take) to what to do and say about it.

use it to: run the demo for a room without improvising Open /script

How to test it

Six manual test cases with expected outcomes and deliberate non-bugs called out: book via chat, delay vs cancel a leg, attach a meeting, cancel the whole trip, set a spending cap and watch the agent act (or refuse), and share by role — the host link must show zero prices on every endpoint.

use it to: break it on purpose and know what counts as broken Open /test
